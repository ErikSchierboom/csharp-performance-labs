# Suggested answers

1. **Exact vs noisy.** *Allocation per run/request* and *GC collection counts* are **exact** (deterministic for a given input): gate hard, block merges. *Retained memory after GC* is near-exact: gate hard. *Wall/CPU time* and *latency percentiles* are **noisy**: gate with headroom, scale by a calibrated machine factor (this harness does), and prefer "warn, then block on a second failure". Track everything as a time series regardless.
2. **SLO -> budget.** p99 SLO 300 ms and baseline 180 ms: budget **240–270 ms** (i.e. 80–90% of the SLO, so a regression trips the gate *before* it trips the SLO, but above baseline + noise). Allocated bytes per request: **baseline + 10–15%** (e.g. 1.4 MB): it's exact, so you can be tight. Error rate: **0** (any error under a gated load test is a failure). Budgets in reference-ms scaled per machine, as in this harness.
3. **Noise sources and mitigations.** *Shared/noisy runners*: dedicated or self-hosted runners; use CPU-time rather than wall time where possible; median of N runs (harness uses 5). *Machine speed differences*: machine-speed calibration factor (harness `MachineFactor`). *JIT tiering/warm-up*: time-based warm-up before measuring (harness, from v2). *Thermal throttling*: fixed run order, cool-down, pinned frequency on dedicated hardware.
4. **Re-run policy.** A gate that needs a retry to pass is telling you it's flaky: log every retry. Reasonable: retry once automatically; if it fails twice, block; if it passes only on retry more than a few times a month, fix the test or widen the budget *with a reviewed change* rather than letting retries paper over it. The cost: a retry hides real intermittent regressions (e.g. a race that costs 1 run in 10).
5. **Gaming.** Raising a budget, shrinking the workload, or deleting a metric all turn the gate green. Rule: **any change to a budget or to `Program.cs` needs a reviewer from outside the author's team and a written reason**; keep budgets in a file with a CODEOWNERS entry. (In this repo, `Program.cs` is shared between exercise and solution and marked "don't edit" for the same reason.)
6. **Drift ratchet.** Store the *last accepted* values (e.g. `budgets.json`); CI fails if a budget increases; improvements auto-suggest a tighter budget. Loosening requires an explicit exception with an issue link.

## The point
A gate is a **contract about the product** (SLO) translated into things a machine can check cheaply and reliably. Exact metrics are the backbone; noisy metrics need policy.
